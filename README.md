# HERO-FILE-EXTRACTOR

أداة Python تعمل على GitHub Actions (أو يشغّلها Claude مباشرة) لفحص الأرشيفات، وفك المتداخل منها، واستخراج أنواع محددة من الملفات (مثل مجسمات الأشجار بصيغة GLB)، وترتيبها في مجلدات واضحة مع تقرير.
**لا يوجد تطبيق أندرويد ولا APK في هذا المشروع.**

## ما تفعله الأداة
- الصيغ: ZIP، RAR (RAR4 وRAR5)، 7Z، TAR، GZ، BZ2، XZ، وكذلك `.tar.gz` و`.tar.bz2` و`.tar.xz`.
- الأرشيفات المتداخلة (ZIP داخل 7Z داخل TAR.GZ …) تُكتشف من **محتوى** الملف لا من امتداده، وتُفك حتى عمق 10.
- ملفات docx/xlsx/pptx/apk/jar تُعامل كمستندات ولا تُفك (يمكن تفعيل ذلك بـ `--unpack-containers`).
- فحص بنية الملفات: PNG وJPEG وGIF وWEBP وBMP، MP4/MOV/M4A، WAV/FLAC/OGG/MP3، GLB/GLTF/OBJ/STL/PLY/FBX/BLEND/DAE، PDF وملفات Office.
  لـ GLB تُقرأ أيضاً أسماء العقد والمجسمات والخامات وعدد المثلثات، ويمكن البحث بها (مثلاً ملف اسمه `model_17.glb` لكن بداخله عقدة `OakTree`).
- الفلاتر: `--type` و`--category` و`--match` و`--exclude`.
- الأصول لا تُعدَّل ولا تُحذف: تُفتح للقراءة فقط، وفي نهاية التشغيل يتحقق التقرير من أنها لم تتغير (sha256 + الحجم + وقت التعديل).
- الملفات الكبيرة: القراءة بالتدفق (Streaming) دون تحميل الملف في الذاكرة. حدود الأمان: حجم إجمالي، حجم للعنصر، عمق، عدد عناصر، مساحة القرص.
- ملفات تالفة: تُعزل في `_needs_review/`، والأرشيف المبتور تُنقذ منه العناصر السليمة، والأرشيف المتداخل الذي تعذر فكّه يُحفظ في `_unreadable_archives/` حتى لا يضيع.
- مكررات (محتوى متطابق) لا تُنسخ مرتين وتُسجَّل في التقرير.

## الاستخدام من الهاتف (بدون كمبيوتر)

### 1) ارفع الملف إلى GitHub
- **ملف حتى 25MB:** افتح المستودع في المتصفح ← **Add file** ← **Upload files** ← اختر الملف ← ضعه في مجلد اسمه `uploads` ← **Commit changes**.
- **ملف أكبر (حتى 2GB):** المستودع ← **Releases** ← **Draft a new release** ← اكتب أي اسم لـ Tag ← اسحب الملف في خانة **Attach binaries** ← **Publish release**. ثم انسخ رابط الملف (اضغط مطولاً على اسم الملف ← Copy link).
- (الرفع الأول إلى `uploads` يحتاج إنشاء المجلد: عند الرفع اكتب `uploads/` قبل اسم الملف في خانة المسار.)

### 2) اختر طريقة التشغيل

**أ) عن طريق Claude (الأسهل):** أرسل لـ Claude رابط المستودع (يجب أن يكون **عاماً Public**) مع المهمة بالعربية، مثل:
- «افحص الأرشيفات في uploads وأعطني قائمة بما فيها دون استخراج.»
- «استخرج كل الأشجار بصيغة GLB.»
- «استخرج البيوت والشخصيات والصخور ورتبها في مجلدات.»

Claude يشغّل الأداة، ويعطيك الملفات جاهزة للتنزيل والتقرير. تعليماته الكاملة في `CLAUDE.md`.

**ب) عن طريق GitHub Actions بنفسك:** المستودع ← **Actions** ← **Extract (استخراج)** ← **Run workflow** ← املأ الحقول:

| الحقل | مثال |
|---|---|
| source | `uploads` |
| source_url | رابط ملف Release إن رفعت ملفاً كبيراً |
| types | `glb` |
| match | `trees=tree\|pine\|palm\|oak,houses=house\|cottage,rocks=rock\|stone` |
| list_only | فعّلها لفحص فقط دون استخراج |
| publish | `artifact` أو `release` أو `branch` |

### 3) خذ النتائج
- افتح صفحة التشغيل: **التقرير يظهر أسفلها مباشرة** (Summary).
- **artifact:** في أسفل الصفحة `extraction-results` ← تنزيل (يعمل من متصفح الهاتف؛ إن لم يظهر زر التنزيل فعّل «موقع سطح المكتب»). يُحذف تلقائياً بعد 90 يوماً.
- **release:** يُنشأ Release جديد فيه `results.zip` برابط ثابت (حتى 2GB).
- **branch:** تُحفظ النتائج في فرع `extraction-results` داخل `run-<رقم>/` (الملفات أقل من 95MB فقط).

## الملفات الناتجة
- `models_3d/glb/…` أو `trees/glb/…` (عند استخدام `--match`) — الملفات المستخرجة.
- `REPORT.md` — تقرير عربي: المستخرج والتالف وغير المدعوم والمشفّر وحالة الأصول.
- `report.json` و`manifest.csv` (كل ملف مع مصدره الكامل داخل الأرشيفات وبصمته) و`inventory.csv` (كل ما رُئي داخل الأرشيفات).

## سطر الأوامر
```
pip install -r requirements.txt        # و sudo apt install unrar لملفات RAR
python -m hero_extract uploads -o results --type glb --match "trees=tree|pine|palm"
python -m hero_extract file.7z -o results --list-only
```
الخيارات كاملة: `python -m hero_extract --help`.

## حدود معروفة (بصراحة)
- **الملفات المحمية بكلمة مرور** تُسجَّل في التقرير ولا تُفك.
- **الأرشيفات المجزأة** (`.part1.rar` و`.z01` و`.7z.001`) غير مدعومة.
- فحص السلامة **بنيوي**: يلتقط الملفات المبتورة والمعطوبة والمسمّاة خطأً، ولا يفك ترميز الصور أو الفيديو أو الصوت بالكامل.
- أسماء الداخل في FBX وBLEND لا تُقرأ؛ المطابقة فيها تعتمد على اسم الملف ومساره فقط.
- في 7Z وRAR، الملفات ذات الامتداد غير المعروف تُفك مؤقتاً لفحصها بحثاً عن أرشيف مخفي (يستهلك مساحة مؤقتة)؛ في ZIP وTAR يُفحص رأس الملف فقط.
- المطابقة بالكلمات تعتمد على أسماء الملفات والمجلدات (وأسماء GLB/OBJ/DAE الداخلية)، فهي لا «ترى» شكل المجسم. راجع التقرير دائماً.
- GitHub Actions: مساحة القرص ~14GB وأقصى 6 ساعات للتشغيل.

## الاختبار
`python -m pytest tests` — 18 اختباراً تبني أرشيفات حقيقية (متداخلة، تالفة، مبتورة، مشفّرة، RAR حقيقي) وتتحقق من النتائج. تعمل تلقائياً على كل push عبر `tests.yml`.
ملفات RAR الصغيرة في `tests/data` مأخوذة من مشروع [rarfile](https://github.com/markokr/rarfile) (ترخيص ISC).
